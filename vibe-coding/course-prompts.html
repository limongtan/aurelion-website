From Zero to App Builder

Open an empty folder in VS Code, open Claude Code, and paste these one at a time. Change only the words in [BRACKETS]. Never paste a password into the chat.

1 Get ready (P01) 2 Build (P02–P03) 3 Save and publish (P04–P05) 4 Understand and test (P06–P08) 5 Fix and explain (P09–P10) 6 Grow and finish (P11–P13)

1 Get ready

P01 Check my laptop Before you build, check that your laptop has the tools you need. 
I am a complete beginner on Windows and I have never coded. Do all the technical work for me and explain everything in plain English.

Check this laptop has what I need to build a web app and put it online: Python 3, Git and the GitHub tool (gh).

For anything missing, install it from the official source, one at a time. Tell me first if Windows will show an "Allow changes?" popup.
Apart from those installs, don't touch any files outside this folder.

Finish with a short list of what is OK, then the word READY, or NOT READY with plain steps for me.

2 Build

P02 Tell and Detail: build my portfolio app Start here when you’re ready to build your portfolio. 
I have never coded. Build me a simple portfolio web app in this folder and do all the technical work yourself. Choose sensible defaults instead of asking me technical questions.

ABOUT ME
Name: [Aina Rahman]
The job I want: [junior data analyst]
About me: [Fresh accounting graduate who likes finding patterns in messy numbers.]
My projects: [1. Final-year project on small business cash flow. 2. Volunteer sign-up sheet for my campus club.]

WHAT THE APP DOES
1. A public home page with my name, the job I want, the About me text, my projects, and a contact form asking for name, email and message.
2. After sending, the visitor sees a thank-you message.
3. A private page at /admin that lists all messages, newest first, with date and time.

HOW TO BUILD IT
- Use Python with Flask.
- Save messages in a real database: Postgres when a DATABASE_URL setting exists, otherwise a local SQLite file.
- My home page must still open if the database is ever unavailable. In that case only the contact form shows a friendly message.
- Messages are private, so the private page must ask for a password. Read it from a setting called ADMIN_PASSWORD. Create a random password in a private .env file and keep that file out of GitHub. Never write a password in the code.
- The private page asks for the password only, with no username.
- Check the form properly: every field is required, the email must look like an email, and bad input must not crash the app.
- Show all dates and times in Malaysia time.
- It must look clean and work on a phone.
- Use a free port, and check that the page that opens really is this app.
- Install what it needs inside this folder only.
- Make it ready to run on an online host later: list its requirements and read the port from a setting.

WHEN YOU FINISH
Start the app and test it yourself: send a test message, then log in and check it shows on the private page. Delete your test data.
Then tell me in plain English: the link to open, how to see my password in VS Code, and 3 things I should try. Leave the app running for me, and restart it yourself whenever you change something.
P03 Improve: make it mine After opening your app, add your skills, LinkedIn profile and colours. 
I opened my app. Please improve it:
1. Add a section called Skills with these: [Excel, SQL basics, presenting to clients].
2. Add a button that opens my LinkedIn page: [https://www.linkedin.com/in/your-name].
3. Make the page look more professional, using colours that suit [a young data analyst].

Keep everything else working. Test it again yourself, delete your test data, restart the app so I can see the changes, then tell me in one or two sentences what changed.

3 Save and publish

P04 Save my work to GitHub When your app works on your laptop, save a private copy on GitHub. 
Save my project to a new PRIVATE GitHub repository called [my-portfolio].

If I am not logged in to GitHub, start the login for me and tell me exactly what to click.
Before you upload, check that no password, .env file or database file will be uploaded.

Then give me the link to my repository and explain in one sentence what GitHub does for me.
P05 Deploy: put it on the internet After saving to GitHub, put your portfolio online. 
Put my app live on the internet using Render's free plan, so anyone can open it. Do all the technical work yourself, and tell me exactly what to click on the Render website, one step at a time.

1. Add a Render blueprint file (render.yaml) with a free web service and a free Postgres database, both in the Singapore region. DATABASE_URL comes from that database. Block outside connections to the database. Render must generate ADMIN_PASSWORD and any other secret randomly. Save this to GitHub, and check the file really is on GitHub.
2. Then guide me on the Render website: log in with GitHub, allow Render to see this repository, click New, then Blueprint, connect my repository, and deploy it. Wait for me while I do this, and ask me to paste my live link when it is ready.
3. Tell me where on Render I can see my ADMIN_PASSWORD. Never ask me for that password and never show it in the chat.
4. When I paste my live link, test it yourself: the home page opens, and /admin refuses a wrong password. Then ask me to send a message from my phone, log in to /admin and tell you if I can see it.

If Render asks for a payment card or money at any point, stop and tell me before I go on.

Finish with my live link, what was tested and the result, and the date my free database expires, which is 30 days from today.

4 Understand and test

P06 How my app really works Once the contact form works, see how a message reaches your private page. 
Explain my own app to me in plain language, as if I have never coded. Don't change anything.

Use a small table with these rows: Front end (what visitors see and click), Back end (the logic behind the scenes), Database (where information is kept). For each row give a one-sentence meaning, the exact files in my project, and one thing from my app as an example.

Then follow one message step by step, from a visitor pressing Send to it appearing on my private page. Keep the whole answer under 150 words.
P07 Automatic tests before going live Before your next update goes live, set up tests that run on their own. 
Add automatic tests to my app, and explain them in plain words. Test that the home page opens, that a good message is saved, that a bad message is refused, and that the private page refuses a wrong password.

Make them run by themselves on GitHub every time my work is saved to GitHub. In render.yaml, set autoDeployTrigger to checksPass, so a failed test can't put a broken app online.

Run the tests now and show me the result in a simple list. Save my work to GitHub, check the tests passed on GitHub too, then check my live link still works: [paste your live link].
P08 Practice: break it on purpose When you’re ready to practise debugging, create a form error on your laptop. 
I want to practise finding errors. On this laptop only, break my app on purpose so that pressing Send on the contact form fails. Don't save this to GitHub and don't put it online. Keep the app running on this laptop, and save its errors to a file called app.log.

Don't tell me what you broke. Give me these steps instead:
1. How to open the browser's console and network tabs with F12.
2. What to do to see the error.
3. Which words to copy for you, including the newest error in app.log.

5 Fix and explain

P09 Report a problem to AI After the form fails, use the error message to ask for a fix. 
On my laptop, on the home page, I filled in the form and pressed Send. I expected a thank-you message, but it failed. Here is what I can see: [paste the red error from the console or network tab, and the newest error from app.log].

Find the cause and fix it, test it again yourself, and tell me in one sentence what was wrong. Then show me that my laptop's files match the last version saved on GitHub.
P10 Write my app's manual Once the app is live, write down how to run and update it. 
Write a README file for my app, for someone who has never coded. Explain what the app does, my live link, how to start it on my laptop, where to see my password, how to make a change using Claude, and what to do if something breaks.

Also explain my free plan: the live site sleeps when nobody visits and takes about a minute to wake up, and my free database expires on [the date from P05]. Say what stops working on that date and what to do before it: copy my messages from the private page, or pay Render to keep the database.

Put no passwords in it. Save my work to GitHub, and check the live link still works afterwards.

6 Grow and finish

P11 Add a database feature When you’re ready to manage replies, add a filter and a download. 
Add a new feature to my app: on the private page, each message gets a "Mark as replied" button, I can show only the messages not yet replied to, and a "Download Excel" button downloads all messages as a file Excel can open.

Existing messages on my live app must not be lost. Update the automatic tests to cover this.

Test it on my laptop, delete your test data, save to GitHub, and wait until it is live. Then check that my live link still opens and tell me exactly what to try on the live private page myself: mark a message as replied, and download the file. Don't ask for my password. Tell me the result in simple words after I report back.
P12 Go back to an old version After adding the reply button, practise switching between saved versions. 
Teach me how to go back in time, using my real app:
1. Show me my saved versions as a simple list, with the date and what each one changed.
2. Use git revert to bring my LIVE app back to the version from before the "Mark as replied" feature, without losing any data. Wait until it is live, then ask me to check on the private page that the button has gone.
3. Then bring the latest version back, wait until it is live, and ask me to check that the button has returned and my messages are still there.

Explain in two sentences what happened, and add this to CLAUDE.md so I can do it again by asking you. Don't ask for my password.
P13 Final check before I present Before you present, check the live app and prepare what you’ll say. 
I am about to show my app to the class. Check my LIVE link for me and fix small problems: [paste your live link]
- Every public page and button works, on phone size and laptop size.
- The private page and its download refuse anyone without the password.
- No password or private file is in my GitHub repository, including old versions.
- My repository is private.
- My public page shows no IC number, home address or anything else I wouldn't give a stranger.
- For Malaysia's PDPA: the form says in simple words why I collect the details and who to contact to see or delete them. Add it if it's missing, using [aina@example.com] as the contact.

Save and test any fix on the live link. Then give me a short list of what passed and what you fixed, 3 sentences I can say when I present, 2 lines for my CV, and one honest answer for an interview when they ask how I built it with AI.
